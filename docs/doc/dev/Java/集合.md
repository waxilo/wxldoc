## ArrayList

数据结构：Object数组

### 扩容机制

1. 当 `size + 1 > capacity` 时，触发`grow`扩容。
2. 空数组扩容为10，非空数组1.5倍扩容
```java
	// 1.5 倍扩容
	int newCapacity = oldCapacity + (oldCapacity >> 1); 
	
	// 数据拷贝，底层实现是System.arraycopy
	elementData = Arrays.copyOf(elementData, newCapacity); 
```

## HashMap

数据结构：HashTable + 链表\红黑树

### 多线程问题

#### 1. **数据不一致（脏读/丢失更新）**

- 多个线程同时执行 `put()` 或 `remove()` 操作时，由于没有同步机制，可能导致：
    - 某些写入操作被覆盖或丢失；
    - 读取到中间状态的数据（例如部分更新的值）。

#### 2. **死循环（JDK 7 及更早版本中特别严重）**

- 在 JDK 7 及之前的 `HashMap` 实现中，当发生哈希冲突时使用**链表**存储元素。
- 在扩容（resize）过程中，会将链表**反转**。如果多个线程同时触发扩容，可能造成链表**成环**（形成循环引用）。
- 后续对该 `HashMap` 的 `get()` 操作会陷入**无限循环**，导致 CPU 占用 100%，程序卡死。

> ⚠️ 虽然 JDK 8 改进了扩容逻辑（使用尾插法避免成环），**但仍然不是线程安全的**，仍可能出现数据错乱等问题。

#### 3. **size 统计错误**

- `HashMap` 内部维护一个 `size` 字段记录元素数量。
- 多线程并发 `put` 时，`size++` 不是原子操作，可能导致最终 `size()` 返回错误的值。

#### 4. **空指针异常（NullPointerException）**

- 在某些竞态条件下，可能读取到尚未完全初始化的桶（bucket）或节点，导致 NPE。

## LinkedHashMap

数据结构：HashMap + 双向链表

**特点**：
- 继承自 HashMap，所有功能与 HashMap 类似
- 维护了一个双向链表，保证插入顺序或访问顺序
- 通过 accessOrder 参数控制访问顺序
  - false：按插入顺序（默认）
  - true：按访问顺序（LRU 缓存实现基础）

**应用场景**：
- LRU 缓存实现
- 需要保持插入顺序的场景

## CopyOnWriteArrayList

数据结构：Object 数组

### 写操作

1. 获取写锁，每次仅允许一个写请求，阻塞其他
2. 复制数组副本，在副本上进行写操作
3. `volatile` 的引用覆盖操作，将副本覆盖原引用

### 读操作

- 直接从原数组读取，无锁

**优点**：
- 读操作性能极高，不需要加锁
- 适合读多写少的并发场景

**缺点**：
- 内存占用大（每次写操作都要复制数组）
- 数据一致性问题：只能保证最终一致性，不能保证实时一致性

## ConcurrentHashMap

数据结构：HashTable + 链表/红黑树 + Node 锁

### JDK 7 vs JDK 8

| 特性 | JDK 7 | JDK 8 |
| ---- | ----- | ----- |
| 数据结构 | Segment 数组 + HashEntry 数组 + 链表 | Node 数组 + 链表/红黑树 |
| 锁粒度 | Segment 锁（分段锁） | Node 锁（CAS + synchronized） |
| 并发度 | Segment 数量 | Node 数量 |

### JDK 8 的优化

- **数组初始化**：CAS 保证线程安全
- **Node 写入**：synchronized 锁住头节点
- **链表转红黑树**：链表长度 ≥ 8 且数组容量 ≥ 64
- **扩容**：多线程协作，每个线程负责一部分区间

## PriorityQueue

数据结构：数组维护的堆

**特点**：
- 默认是小顶堆（最小元素在堆顶）
- 可以通过传入 Comparator 自定义排序规则
- 不允许 null 元素
- 线程不安全

**常用方法**：
- add()/offer()：添加元素
- remove()/poll()：取出并删除堆顶元素
- element()/peek()：查看堆顶元素

**应用场景**：
- Top K 问题
- 任务调度
- 优先队列

## TreeMap

数据结构：红黑树

**特点**：
- 键有序（自然排序或自定义排序）
- 非线程安全
- 时间复杂度：O(logn)

**常用方法**：
- firstKey()/lastKey()：获取第一个/最后一个键
- ceilingKey()/floorKey()：获取大于等于/小于等于给定键的键
- headMap()/tailMap()/subMap()：获取子 Map

## HashSet

数据结构：底层使用 HashMap

**特点**：
- 元素无序且不重复
- 允许 null 元素
- 非线程安全
- 查找、插入、删除复杂度 O(1)

## TreeSet

数据结构：底层使用 TreeMap

**特点**：
- 元素有序（自然排序或自定义排序）
- 不允许 null 元素
- 非线程安全
- 查找、插入、删除复杂度 O(logn)

## ArrayList vs Vector

| 特性 | ArrayList | Vector |
| ---- | --------- | ------ |
| 线程安全 | 不安全 | 安全（方法都加了 synchronized） |
| 性能 | 高 | 低 |
| 扩容倍数 | 1.5 倍 | 2 倍（或自定义） |
| 推荐使用 | 是 | 否（已过时） |

## HashMap vs Hashtable

| 特性 | HashMap | Hashtable |
| ---- | ------- | --------- |
| 线程安全 | 不安全 | 安全（方法都加了 synchronized） |
| null 键值 | 允许 | 不允许 |
| 性能 | 高 | 低 |
| 推荐使用 | 是 | 否（已过时） |

## 集合选择建议

| 场景 | 推荐类 |
| ---- | ------ |
| 需要快速随机访问 | ArrayList |
| 需要频繁在头尾插入删除 | LinkedList |
| 需要键值对快速查找 | HashMap |
| 需要键值对有序 | TreeMap |
| 需要键值对线程安全 | ConcurrentHashMap |
| 需要元素不重复 | HashSet |
| 需要元素有序且不重复 | TreeSet |
| 需要优先队列 | PriorityQueue |
| 读多写少的并发列表 | CopyOnWriteArrayList |
