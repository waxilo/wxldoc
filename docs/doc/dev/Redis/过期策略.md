针对设置有过期时间的key，reids主要使用以下3中进行key删除：

| 过期策略 | 描述                                                                 | 优点             | 缺点           |
| ---- | ------------------------------------------------------------------ | -------------- | ------------ |
| 惰性删除 | 当每次访问key时，检查是否过期，过期则删除                                             | CPU友好          | 不访问的key无法被移除 |
| 定期删除 | redis每隔一段时间抽取一批设置了过期时间的key，<br />删除其中已过期的key；如果删除数量超过抽取数量25%，再次抽取。 | 折中方案           | 非即时删除        |
| 定时删除 | key绑定一个定时器，当key过期立即删除                                              | 删除及时<br />内存友好 | 需创建大量定时器     |

## 高频面试题

### Q1: Redis 的过期 key 删除流程

Redis 采用 **惰性删除 + 定期删除** 的组合策略：

**惰性删除流程**：
1. 客户端访问 key 时，检查是否过期
2. 过期则立即删除，返回空
3. 未过期则返回数据

**定期删除流程**：
1. 每隔一段时间（`hz` 配置，默认 10），执行一次
2. 从设置了过期时间的 key 集合中随机抽取一部分
3. 检查并删除过期的 key
4. 如果删除数量 > 抽取数量 × 25%，继续抽取

### Q2: 设置过期时间的方式及区别

| 命令 | 作用 | 返回值 |
|------|------|--------|
| `EXPIRE key seconds` | 设置秒级过期 | 1=成功，0=失败 |
| `PEXPIRE key ms` | 设置毫秒级过期 | 1=成功，0=失败 |
| `EXPIREAT key timestamp` | 设置过期时间戳（秒） | 1=成功，0=失败 |
| `PEXPIREAT key ts` | 设置过期时间戳（毫秒） | 1=成功，0=失败 |
| `TTL key` | 查看剩余生存时间（秒） | -1=永不过期，-2=不存在 |
| `PTTL key` | 查看剩余生存时间（毫秒） | -1=永不过期，-2=不存在 |

**注意事项**：
- `SET key value EX seconds` 可以同时设置值和过期时间
- 修改 key 的值不会影响过期时间
- `RENAME` 会复制过期时间到新 key

### Q3: 大量 key 同时过期会有什么影响？

**问题**：
- 大量 key 在同一时刻过期
- 定期删除时可能阻塞主线程
- 数据库突然需要加载大量数据到内存

**解决方案**：
1. 给过期时间添加随机偏移量
```python
# 错误的写法
expire_time = timestamp + 3600

# 正确的写法
expire_time = timestamp + 3600 + random.randint(0, 300)  # 添加 0-5 分钟随机偏移
```

2. 使用逻辑过期（不设置真实过期时间）
```python
# 使用逻辑过期字段
data = {
    "value": actual_data,
    "logic_expire": timestamp + 3600
}

# 读取时检查
if current_time > data["logic_expire"]:
    # 异步更新缓存
    refresh_cache()
```

### Q4: 如何实现延迟过期？

**场景**：需要延迟过期，而不是立即过期

**方案 1：轮询检查**
```python
def get_with_delay_expire(key, delay=60):
    data = redis.get(key)
    if data:
        # 检查是否需要延迟
        if is_about_to_expire(key):
            redis.expire(key, delay)
    return data
```

**方案 2：使用 Sorted Set**
```python
# 写入时
redis.zadd("delay:keys", {key: current_time + delay_time})

# 读取时检查
if redis.zscore("delay:keys", key):
    if current_time >= redis.zscore("delay:keys", key):
        redis.expire(key, new_ttl)
        redis.zrem("delay:keys", key)
```

### Q5: 过期 key 对内存的影响

**问题**：
- 过期 key 仍然占用内存，直到被删除
- 大量过期 key 可能导致内存持续增长

**监控命令**：
```bash
# 查看过期 key 统计
INFO stats | grep expired

# 查看已过期的 key 数量
SCAN 0 COUNT 1000
# 手动检查并删除
```

### Q6: RDB 和 AOF 对过期 key 的处理

| 持久化方式 | 对过期 key 的处理 |
|------------|------------------|
| RDB 写入 | 已过期的 key 不会被写入 |
| RDB 读取 | 主模式：已过期的 key 会被忽略<br />从模式：已过期的 key 会被正常读取 |
| AOF 重写 | 已过期的 key 不会被写入 |
| AOF 执行 | 已过期的 key 被删除时，会在 AOF 文件中追加 DEL 命令 |
